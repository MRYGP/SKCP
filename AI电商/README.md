# AI电商研究库

GitHub 仓库：[MRYGP/SKCP](https://github.com/MRYGP/SKCP)

这个目录收集并整理了关于“平台原生 AI 时代，第三方 AI 电商工具还能如何生存”的系列研究材料。

核心结论：不要复制第三方公司的产品形态，要复制它们的护城河结构。真正有机会的方向不是泛泛“AI 赋能电商”，而是用 AI 降低长尾商家的服务交付成本，把原来只有大商家才用得起的运营、客服、商品资料、售后、复购和数据分析，压缩成小商家也买得起的经营服务。

## 推荐阅读顺序

1. `AI电商综合研究报告.md`  
   总结五份研究报告后的主结论，适合作为入口。

2. `对标库-第三方幸存者.md`  
   按护城河类型整理可对标公司，重点看“抄结构，不抄产品形态”。

3. `参考意见书1.md`  
   把研究结论转成可执行的机会排序，重点是“人工 + AI 服务包”。

4. `参考意见书2.md`  
   聚焦京东礼品定制“培训班课后督学”项目，判断是否值得做、怎么验证。

5. `AI赋能电商-方向判据.md`  
   用来判断一个方向是否值得继续推进。

## 当前优先机会

按现有材料，优先验证顺序是：

1. 礼品定制 / 垂直小电商的“客服 + 订单 + 售后执行助手”
2. 产业带商品资料多平台助手
3. 本地小店老客唤醒小工
4. 多平台经营异常日报
5. 垂类视觉内容工具

## 研究原则

- 不做泛 AI 工具，优先找经营入口。
- 不直接抄产品，抄护城河结构。
- 不优先做独立 SaaS，先用“人工 + AI”验证服务包。
- 不把试用兴趣当 PMF，看真实付费、授权、复购和执行权限。
- 不把“平台没做”直接等同于机会，先验证客单价、交付成本和获客成本。

## 建议的下一步

最小验证可以从 3-5 个礼品定制或垂直小电商商家开始，人工接管一部分客服、订单跟进和售后流程，用 AI 提升交付效率，7-14 天后测试商家是否愿意付 499-999 元/月。
