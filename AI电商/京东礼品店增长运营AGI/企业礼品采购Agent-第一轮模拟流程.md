# 企业礼品采购 Agent · 第一轮模拟流程

## 一、目的

这不是做一个完整 Agent 产品，而是用人工 + AI 模拟一次“企业采购需求”和“礼品供给能力”的直接连接，验证平台外连接是否真的可能。

要回答的问题：

> 企业采购任务能不能不从“逛平台店铺”开始，而从“采购需求拆解 → 多供给方询价 → 可审核方案 → 履约路径”开始？

## 二、适用场景

优先选择企业礼品、批量定制、会议活动、员工福利、年会礼品、客户答谢、生日会礼品等场景。

不优先选择普通 C 端零售单：单件、低客单、无定制、无复购、无发票/合同要求的订单无法验证 Agent-to-Agent 的价值。

## 三、输入材料

### 1. 采购方需求

至少采集：

- 采购场景：年会 / 会议 / 员工生日 / 客户答谢 / 开业 / 周年庆 / 表彰；
- 人数 / 数量；
- 单人预算或总预算；
- 交付时间；
- 收货地；
- 是否需要 logo / 刻字 / 包装 / 礼盒；
- 是否需要发票 / 合同 / 对公付款；
- 风格偏好：有面子、实用、不浮夸、年轻化、商务、纪念性；
- 禁忌：不能太廉价、不能易碎、不能交期不稳、不能侵权。

### 2. 供给方能力

从朋友店或其他供给方采集：

- 可供品类；
- 起订量 MOQ；
- 定制方式：logo、刻字、丝印、包装、贺卡、礼盒；
- 单价区间；
- 交期；
- 库存 / 排产边界；
- 可开发票类型；
- 过往案例；
- 售后责任边界；
- 哪些需求不能接。

## 四、模拟流程

### Step 1：需求拆解

把一句采购需求拆成结构化采购任务。

示例：

> 下个月员工生日会，30 人，预算 200 元/人，要有面子但不浮夸，最好能印公司 logo，下周五前到。

拆成：

- 场景：员工生日会；
- 数量：30 份；
- 总预算：6000 元；
- 风格：有面子、不浮夸；
- 定制：logo；
- 交期：下周五前；
- 风险：交期、logo 文件、包装、发票。

### Step 2：生成供给方询价单

输出给供给方的标准询价单：

- 推荐 2-3 个商品方案；
- 每个方案给出单价、总价、交期、定制方式、包装、发票；
- 标明不确定项：logo 文件、收货地、是否打样、是否开票；
- 标明无法满足的部分。

### Step 3：生成采购方对比表

把多个供给方案整理成采购方能看懂的对比：

| 方案 | 单价 | 总价 | 交期 | 定制能力 | 风险 | 推荐理由 |
|---|---:|---:|---|---|---|---|
| A | | | | | | |
| B | | | | | | |
| C | | | | | | |

### Step 4：输出可审核推荐

不是只说“推荐 A”，而是交付可审核理由：

- 为什么最符合预算；
- 为什么交期风险最低；
- 为什么显得有面子；
- 哪些需求未确认；
- 如果客户更重视价格/交期/面子，备选方案是什么。

### Step 5：生成确认清单

采购方下单前必须确认：

- 数量；
- logo 文件；
- 包装；
- 收货地；
- 发票；
- 合同/付款方式；
- 交期；
- 售后责任。

### Step 6：标记平台角色

记录这次交易中平台到底提供了什么：

- 流量入口；
- 商品展示；
- 支付担保；
- 发票/合同；
- 物流；
- 售后仲裁；
- 评价背书。

如果平台只承担支付/履约/发票通道，而需求拆解和方案选择都在平台外完成，就说明 Agent 层有价值。

## 五、输出物

每次模拟必须输出：

1. 采购任务卡；
2. 供给方询价单；
3. 方案对比表；
4. 可审核推荐；
5. 下单确认清单；
6. 平台角色拆解；
7. 这次流程中 AI 节省了哪部分人力。

## 六、Go / Kill

### Go 信号

- 采购需求能被结构化；
- 供给方愿意按询价单回复；
- 采购方愿意看对比方案；
- AI 明显减少需求拆解、报价整理、方案生成时间；
- 平台不是价值创造核心，只是某些环节通道；
- 这套流程可复用到第二个采购任务。

### Kill / 降级信号

- 采购任务太简单，直接平台搜索即可；
- 供给方报价不稳定，无法形成可审核推荐；
- 采购方只信京东企业购，不接受平台外方案；
- 发票、合同、支付、售后责任无法处理；
- AI 输出只是漂亮话，没有减少真实沟通成本。

## 七、第一轮最小动作

本周只做一次模拟，不做系统：

1. 从朋友店找 1-3 个企业采购 / 批量定制旧订单或询价记录；
2. 选一个最典型的需求；
3. 按本流程补齐采购任务卡；
4. 用朋友店作为供给方生成报价方案；
5. 如果可能，再找 1-2 个其他供给方作对照；
6. 输出采购方视角的可审核推荐；
7. 记录平台在这次流程里到底承担了什么。
